# MediaVore — Project Structure

This document describes the high-level layout of the repository, where to find key features, and testing conventions.

Top-level folders

- `lib/` — main app source
  - `core/` — domain entities, shared utilities, theming (`core/theme/app_palette.dart`), and caching
  - `features/` — feature-first organization; each feature contains `data/`, `domain/`, and `presentation/` layers
    - `search/` — discovery, search, media repository abstractions
    - `media_details/` — media detail pages, seen history, notifications, stats
    - `settings/` — app settings and `SettingsProvider`
    - `achievements/` — achievement logic and `AchievementProvider`
  - `main.dart` — app entry

Testing layout

- `test/` mirrors `lib/` structure. Tests follow a feature-focused organization under `test/features/...`.
- `test/helpers/mocks.dart` contains common `Mock`/`Fake` classes used across tests.
- Conventions for widget/unit tests:
  - Use `DefaultLightPalette().toThemeData()` in widget tests so `context.appColors` (theme extension) is available.
  - Register mocktail fallback values for enums or complex types used with `any()`, e.g. `registerFallbackValue(MediaType.movie)`.
  - When instantiating providers that call `_init()` in their constructor (e.g., `SearchProvider`), stub all repository methods called during init (`getAllListNames`, `getListEntries`, `getListPreviews`, `getSeenItems`, `getWatchlistEntries`, `getCacheSize`, `getSeenDbSize`, `getLikedEntries`, `getNotifiedItems`).
  - Prefer asserting provider state over fragile UI lookups for tiny overlay elements (badging icons can be small and clipped in the widget tree). Where you need to interact with UI controls (sliders, taps), simulate user gestures on the control itself.

Requirements and docs

- `DOCS/REQUIREMENTS.md` and `DOCS/requirements/` contain user-visible requirements. Tests should be mapped to the requirement they validate and referenced in the `TODO.md` for coverage tracking.

Quick commands

- Run all tests: `flutter test`
- Run a single test file: `flutter test test/path/to/file_test.dart -r expanded`

Where to look for common helpers

- `test/helpers/mocks.dart` — mock classes and fake entities
- `lib/core/theme/app_palette.dart` — theme extension; include `DefaultLightPalette().toThemeData()` in tests
