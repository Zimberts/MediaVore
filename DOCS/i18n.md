# Localization (i18n)

MediaVore's UI strings come from ARB files, and TMDB data (titles, overviews, …)
is requested in the same language as the UI.

## How the language is chosen

1. The user's override from **Settings → Language**, stored in SharedPreferences
   under `appLanguage`.
2. Otherwise ("System"), the first device locale the app supports.
3. Otherwise, English (`fallbackAppLanguage`).

`LocaleService` (`lib/core/l10n/locale_service.dart`) resolves this choice and
notifies its listeners when the effective language changes. That covers a change
in Settings and a device locale change while "System" is selected.

## Where the language is used

- **UI**: the `MaterialApp` in `main.dart` registers `AppLocalizations` plus the
  Flutter `Global*Localizations` delegates. Widgets read strings through
  `context.l10n.<key>` (`lib/core/l10n/l10n.dart`). Without a delegate in scope,
  as in bare widget tests, this falls back to English.
- **TMDB requests**: `MediaRemoteDataSource._tmdbGet` adds
  `language=<AppLanguage.tmdbTag>` to every request. When a translated overview
  is empty, `getMediaItem` uses the English one.
- **Cache**: `LocaleService` records which language the TMDB cache was filled in
  (`cacheTmdbLanguage`). When it differs from the current language (at startup or
  after a change), `MediaRepositoryImpl` clears the cache and starts a new
  warm-up, so saved items get titles in the new language. `SearchProvider` then
  reloads its lists and results.
- **Saved items**: seen, list, alert and quick-add entries keep the title they
  were saved with. When a title is cached in the current language, that one is
  displayed instead.
- **Filters**: the search/discover filter is `originalLanguage`. It maps to
  TMDB's `with_original_language`, not `language`.
- **Code without a `BuildContext`** (providers, repository progress messages,
  helpers such as `searchErrorMessage` or `releaseSubtitleForItem`): use
  `lookupAppLocalizations(localeService.current.locale)`, or take an optional
  `AppLocalizations` that defaults to `fallbackLocalizations` (English).
- **Dates and numbers**: `main.dart` sets `Intl.defaultLocale` to the active
  locale, so `DateFormat.yMMMd()` and similar follow the app language. Use the
  locale-aware constructors (`DateFormat.yMMMd()`), not hardcoded English
  patterns like `'MMM dd, yyyy'`. Never use a formatted date as a lookup key: the
  stats page keys months with locale-independent values (`_monthKeys`).
- **Genres**: TMDB returns genre names in the request language, so seen history
  can mix languages. Match genres by id with `GenreUtils.getGenreIdByName`, which
  accepts names in every supported language plus TMDB aliases. Display them with
  `GenreUtils.localizedName(context.l10n, id)`. Achievements and stats both rely on
  this.
- **TMDB `status`** (Released, Ended, …) is always English in TMDB; display it
  through `localizedMediaStatus`.
- **Achievements**: titles and descriptions live in
  `assets/achievements/definitions.json` under `translations.<code>`. Display
  them with `achievement.titleFor(context.l10n.localeName)`.
- **Not translated on purpose**: the developer-only debug sections of the
  Notification Center, user list names, and the theme names.

## Adding a language

1. Copy `lib/l10n/app_en.arb` to `lib/l10n/app_<code>.arb` and translate the
   values. `@`-metadata only lives in the English template.
2. Add an entry to `supportedAppLanguages` in `lib/core/l10n/app_language.dart`:

   ```dart
   AppLanguage(code: 'es', tmdbTag: 'es-ES', nativeName: 'Español'),
   ```

3. Add the genre names (`genre*` keys are part of the ARB file) and a
   `translations.<code>` block to every entry of
   `assets/achievements/definitions.json`.
4. Run `flutter pub get` (or `flutter gen-l10n`) to regenerate
   `lib/l10n/generated/`.

`test/core/l10n/translations_test.dart` fails when an ARB file is missing, keys are
missing, or an achievement has no translation for a supported language.

Nothing else in the code needs to change. The Settings dropdown, `supportedLocales` and the
TMDB parameter all derive from that list.

## Adding a string

Add the key to `app_en.arb` and to every other ARB file, regenerate, then use
`context.l10n.<key>`. Missing keys in a non-template file fall back to English
and are reported by `flutter gen-l10n`.
